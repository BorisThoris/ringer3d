# Gameplay parity: web game -> Roblox

Every gameplay mechanic of the web game (`src/`), and where the Roblox port stands on it. Gameplay
means anything that changes what happens on the table or what a player can do there. The look,
the economy, the store and online plumbing are out of scope here.

Status: **same** = matched already; **fixed** = was different, now matches;
**deviation** = kept different on purpose (reason given).

## How it is done

The web game plays every shot on Rapier at a fixed 1/120 s step, from a quantized layout, so a
shot's outcome is a function of (layout, shot, field, map). The port used to roll Roblox's own
physics with hand-converted constants. It now does what the web game does, in pure Luau:

- `Ringer.Sim` is `src/core/physics.ts`: the same world in web units (ring 5.5), the same
  bodies, Rapier's combine rules for friction and restitution, its solver shape (8 substeps a
  step, one pass each, time-of-impact contact normals, the quarter-turn-a-step spin cap), and the
  web game's per-step rules on top (rolling resistance, patches, slopes and hops, cups,
  smash-through, the re-roll after an obstacle, the safety net, the rest test). Drawn at x4.
- `Ringer.Surfaces` is each field's `surface` from `src/game/arenas.ts`.
- The server plays a shot to the end at once (its result is final), sends the shot, and every
  client replays it on the same sim (`ClientModules/Replay`), with `Ringer.Playback` doing the
  web game's fast-forward and capture slow motion. The server waits for the replays.
- `Ringer.Bot` is `src/ai/bot.ts` line for line, imagining candidates on `Ringer.Sim`.

### Measured (2026-11-11/12)

`tests/sim.luau` (generated by `scripts/sim-fixtures.ts` from the web game's own physics) plays
345 shots both ways and fails if parity is lost:

| Group | Shots | Marble position error (web units, ring radius 5.5) | Same outcome |
| --- | --- | --- | --- |
| Free rolls, every field, power 0.25-1, spin -1/0/1 | 84 | mean 0.09 | 99% same taw in/out |
| One mib, hit full and thin, 3 fields | 81 | mean 0.76 | 100% same captures |
| Opening break, every field | 28 | mean 0.51 | capture total 8 / 8 |
| Shots on generated maps (props, cups, pads) | 56 | mean 0.50 | 95% same captures, total 19 / 21 |
| Each piece kind alone (18 kinds x 5 powers) | 90 | mean 0.03-0.68 per kind | 100% same captures and breaks |
| Loose props after a hit | | mean 0.1 | |

A break scatters chaotically (Rapier and this solver can't agree bit for bit), so what has to
match is how the game plays: how far a roll goes, where a hit sends a marble, what a break
captures, what breaks.

`tests/botstats.luau` plays the web runner's skilled-vs-casual matchups (six games a field, the
same maps, seats swapped) on the port. Shots per game, Luau / web:

| Desk | Cul-de-sac | Lawn | Sand | Ice | Gravel | Mini-golf | All |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 14.8 / 10.3 | 15.8 / 21.2 | 12.2 / 14.7 | 33.8 / 36.3 | 8.3 / 7.7 | 28.7 / 31.2 | 13.0 / 9.8 | 18.1 / 18.7 |

Skilled beat casual in 36 of 42 games on the port and 31 of 42 on the web: a two-proportion test
gives z = 1.36 (p = 0.17), so no measurable difference at this sample; per-field shot counts swing
as much between seeds as between ports. `tests/client.luau` replays a whole bot game as a client: all 26 replays end exactly
where the server's sim did. `tests/think.luau` times the Tower's bots on their real floors
(skilled 0.4 s, expert 1.4 s, master 0.9 s, legend 4.0 s on a cloud server); a think runs in
12 ms slices, so three at once never hold the server more than about 40 ms.

| Spin | 0 = sliding launch, +1 = natural roll, -1 = backspin at roll rate; slide-to-roll on friction; spin capped at a quarter turn a step | 0 = roll, +1 = 2x roll, -1 = 1x back | fixed |

| Bumpers | cylinder h 0.45, restitution 1.25 | manual 1.3x kick | fixed |

| Loose props | book, eraser, ruler, mug, pot, brick, cone, log, flowerpot, driftwood, iceblock slide and turn, density per skin | anchored | fixed |

## Marble effects and the shop (`Ringer.MarbleFX`, `Kit.showcase`, `ClientModules/Pets`)

Roblox-only: the web game has no equivalent. Each named marble has a signature effect inside its
glass (flames, lightning, galaxy, snow globe, lava, hearts, rainbow glitter, ghost wisps...), rarer
ones add an aura and orbiting moons; generated marbles get effects by tier, phenomenon and Shiny.
Eight new marbles (the Premium Collection) are sold for coins. Shop cards and the bag reveal draw
rarity glows, rays and twinkles round the preview (particles don't draw in a ViewportFrame); the
bag shakes, bursts with a flash and confetti and plays a sting by rarity. Every player's equipped
marble floats beside them. Checked in `tests/look.luau`.

## Real-client playtest

2026-11-12, Studio 0.747 in the private window station, `scripts/playtest/RingerE2ERig.lua`: a real
client plays a whole match against a Rookie; 30/30 checks. Its first turns are played with input:
a mouse drag turns the aim, pulling the power bar down charges to 80% and letting go shoots; the
right arrow turns the aim, Q sets backspin, holding Space charges and letting go shoots; a touch
drag turns the aim. The events go into the game's own input handlers (`Aim.input`,
`Aim.powerBar`), the functions the engine's UserInputService events call; a test client can't
make the engine send them (VirtualInputManager needs core-script rights). Every shot (18) is
replayed on the client and the next turn comes 0.00-0.18 s after the replay ends; client memory
and object counts stay flat over the match.

A client on a phone may differ from the server in the last bit of `math.sin`/`cos`; the server's
result is final, so at worst a marble snaps a little at rest.
